## 💻 Начало работы и локальное окружение

### Требования
- **Node.js:** `>= 20.0.0`
- **npm:** `>= 10.0.0`
- **Браузер:** Google Chrome или любой совместимый Chromium-браузер

### Установка и запуск

1. Сделайте форк репозитория и клонируйте его:
   ```bash
   git clone https://github.com/<ваш-аккаунт>/dashflow.git
   cd dashflow
   ```

2. Установите зависимости:
   ```bash
   npm install
   ```

3. Запустите расширение в режиме разработки:
   ```bash
   npm run dev
   ```

4. Загрузите собранное расширение в Chrome:
   - Перейдите по адресу `chrome://extensions/`.
   - Включите **«Режим разработчика»** (Developer mode).
   - Нажмите **«Загрузить распакованное расширение»** (Load unpacked).
   - Выберите директорию `.output/chrome-mv3`.

## 📐 Архитектурные принципы и стандарты кода

При разработке в DashFlow соблюдаются следующие правила:

1. **Язык общения и документации:** весь код, комментарии, коммиты, документация и обсуждения ведутся на **русском языке**.
2. **Mobile First:** любой интерфейс и виджет обязаны безупречно адаптироваться от экранов смартфонов (360 px) до 4K.
3. **Никаких HTML-таблиц на мобильных:** на экранах мобильных устройств классические таблицы заменяются на карточные списки (`cards`), `accordion` или `stacked layout`.
4. **Дизайн-система и токены:** все цвета, скругления, тени и отступы должны использовать токены из дизайн-системы (`var(--dashflow-*)`). Запрещено использовать жестко зашитые HEX-цвета и нестандартные полушаги (`gap-1.5`, `w-3.5`).
5. **Доступность (WCAG 2.1 AAA):** интерактивные элементы обязаны иметь размеры не менее $44 \times 44\text{ px}$, контраст текста не менее 4.5:1 (для крупного текста 3:1), поддержку клавиатуры (`focus-visible`, `onKeyDown`) и атрибуты `aria-*`.
6. **Безопасность Manifest V3:**
   - Никакого выполнения удалённого JavaScript (`eval`, `new Function`, внешние скрипты).
   - Изоляция `iframe`: всегда задавать `sandbox="allow-scripts"` **БЕЗ** `allow-same-origin`.
   - Санитизация Custom CSS: блокировка `@import`, внешних `url()` и `javascript:`.
   - Чувствительные разрешения (`network`, `bookmarks`, `geolocation`) требуют явного запроса согласия через `PermissionManager`.

## 🧩 Как добавить новый встроенный виджет

1. Создайте директорию в `src/widgets/built-in/<NewWidget>/`:
   ```text
   src/widgets/built-in/MyWidget/
   ├── MyWidget.tsx       # UI компонент виджета (обёрнут в React.FC<WidgetProps<MySettings>>)
   ├── manifest.ts        # Манифест WidgetDefinition<MySettings> с ленивой загрузкой
   ├── types.ts           # Интерфейс настроек MySettings
   └── index.ts           # Экспорт манифеста и компонента
   ```

2. Определите манифест в `manifest.ts`:
   ```typescript
   import type { WidgetDefinition } from '@/core/widget';
   import type { MySettings } from './types';

   export const myWidgetManifest: WidgetDefinition<MySettings> = {
     id: 'myWidget',
     nameKey: 'widgets.myWidget',
     descriptionKey: 'widgetDesc.myWidget',
     version: '1.0.0',
     iconName: 'Sparkles',
     category: 'utilities',
     surface: 'panel',
     size: {
       defaultW: 4,
       defaultH: 3,
       minW: 2,
       minH: 2,
     },
     settingsSchema: [
       {
         key: 'showDetails',
         labelKey: 'settings.showDetails',
         type: 'boolean',
         defaultValue: true,
       },
     ],
     load: () => import('./MyWidget').then((m) => ({ default: m.MyWidget })),
   };
   ```

3. Зарегистрируйте манифест в `src/widgets/built-in/registry.ts` в массиве `BUILT_IN_MANIFESTS`.
4. Добавьте ключи локализации в `src/core/i18n/locales/ru.ts` и `src/core/i18n/locales/en.ts`.
5. Напишите компонентный тест в `tests/component/widgets/MyWidget.test.tsx`.

## 🔌 Как создать декларативный плагин

Плагины в DashFlow описываются декларативным JSON-манифестом:

```json
{
  "id": "my_custom_rss",
  "name": "Новости разработки",
  "version": "1.0.0",
  "author": "Community Developer",
  "type": "rss",
  "description": "Свежие статьи из мира фронтенда",
  "permissions": ["network"],
  "size": {
    "defaultW": 6,
    "defaultH": 4
  },
  "config": {
    "feedUrl": "https://example.com/rss.xml"
  }
}
```

Типы поддерживаемых декларативных плагинов:
- `rss`: чтение и отображение RSS/Atom лент.
- `embed`: встраивание безопасного внешнего `iframe`.
- `links`: набор полезных ссылок с фавиконками.
- `api`: декларативный опрос JSON API и вывод карточек данных.

## 🧪 Тестирование и проверка качества

Перед отправкой изменений обязательно выполните локальный аудит:

```bash
# 1. Проверка типов TypeScript (0 ошибок)
npm run compile

# 2. Проверка линтером ESLint 9 (0 ошибок, 0 предупреждений)
npm run lint

# 3. Запуск всего набора тестов Vitest
npm test

# 4. Проверка сборки расширения
npm run build
```

## 📝 Конвенция коммитов и процесс Pull Request

### Формат сообщений коммитов (Conventional Commits)

Мы используем формат [Conventional Commits](https://www.conventionalcommits.org/):

```text
<тип>(<область>): <краткое описание на русском языке>

[опциональное подробное описание]
```

**Типы коммитов:**
- `feat`: добавление новой функциональности или виджета.
- `fix`: исправление бага или регрессии.
- `refactor`: рефакторинг кода без изменения внешней логики.
- `docs`: обновление документации или CHANGELOG.
- `test`: добавление или исправление тестов.
- `chore`: служебные правки, обновление зависимостей или конфигурации сборки.

**Примеры:**
- `feat(widget): добавить виджет калькулятора валют`
- `fix(grid): устранить смещение виджетов при ресайзе на мобильных экранах`
- `docs(theme): обновить описание математики контраста в THEME_ENGINE_ARCHITECTURE.md`

### Создание Pull Request

1. Создайте ветку от актуального `main` (`git checkout -b feat/your-feature-name`).
2. Внесите изменения и закоммитьте их.
3. Обновите `docs/CHANGELOG.md` при добавлении значимых изменений.
4. Откройте Pull Request и заполните стандартный шаблон PR.

Спасибо за ваш вклад в развитие DashFlow! 🚀
