# Архитектура первого запуска

## Компоненты и ответственность

- `src/features/onboarding/OnboardingDialog.tsx` показывает шаги выбора языка и города, шаблона рабочего пространства и необязательной настройки Hub.
- `src/features/onboarding/onboarding.ts` проверяет профиль, сохраняет маркер завершения и применяет выбор.
- `src/stores/useDashboardStore.ts` предоставляет защищённый `applyOnboardingPreset()`: он заменяет раскладку только пока snapshot совпадает с исходным стандартным состоянием.
- `src/stores/useAppStore.ts` хранит язык и необязательное предпочтение города; `WeatherWidget` использует город профиля только если у экземпляра виджета не задан собственный.
- `src/entrypoints/newtab/App.tsx` запускает проверку профиля сразу при монтировании, до рендера виджетов; содержимое Dashboard показывается после проверки и гидратации, затем диалог открывается лениво.

## Поток данных

Проверка до рендера виджетов читает маркер `dashflow_onboarding_v1`, сохранённый dashboard, его резервные копии и legacy-ключи пользовательского контента. Диалог предлагается только если эти источники не содержат прежний профиль; ранняя проверка не позволяет стартовым данным виджетов выглядеть как legacy-данные. При принятии выбранный язык применяется через общий `useAppStore`, город сохраняется в `app_city`, затем записывается маркер и выполняется защищённая установка одного из существующих шаблонов `empty`, `morning` или `focus`. При пропуске записывается только маркер завершения. Закрытие диалога равнозначно пропуску.

## Решения и ограничения

- Маркер хранится отдельно от dashboard, чтобы не менять схему его snapshot и миграции.
- Стандартная раскладка может быть заменена только при полном совпадении текущего snapshot с исходным значением по умолчанию. Любое изменение пользователем отменяет seed.
- Наличие сохранённого dashboard, backup или legacy-контента исключает запуск onboarding, включая пустой, но уже мигрированный профиль.
- Город — свободный необязательный текст до 100 символов. Геолокация и разрешения браузера не запрашиваются.
- Сначала применяется явный город экземпляра виджета, затем город профиля, затем город по умолчанию. Если задан город виджета или профиля, сохранённые координаты и автоопределение не подменяют его.
- Hub не подключается автоматически. Пользователь сам раскрывает необязательный блок и выполняет pairing через существующую форму с её явным запросом разрешения.

## Границы и эксплуатация

Хранилище — локальное расширения либо локальная среда StorageAdapter. Ошибка проверки не блокирует dashboard; ошибка сохранения оставляет диалог доступным для повтора. Если раскладка меняется между открытием диалога и подтверждением, marker завершает повторный показ, но seed отказывается перезаписывать пользовательские данные. Ручной сброс профиля должен удалить `dashflow_onboarding_v1`, если требуется повторный первый запуск.
