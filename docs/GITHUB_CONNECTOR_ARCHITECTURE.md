# GitHub polling в локальном Hub

Коннектор создаёт в DashFlow карточки открытых issues и pull requests, назначенных выбранному пользователю, открытых PR с запросом его ревью и открытых issues или PR с индексируемым личным упоминанием. По умолчанию карточки попадают во «Входящие». Для назначения в колонку указывают идентификаторы активной доски и колонки. Статус карточки и её удаление в DashFlow не меняют данные GitHub.

## Контракт и поток данных

- `hub/src/connectors/contract.ts` определяет `PollingConnector` с идентификатором, названием, JSON Schema публичной конфигурации и отменяемым `poll`. Результат содержит черновики DashFlow и устойчивые внешние идентификаторы.
- `github.ts` строит отдельные запросы для issues и PR. GitHub поддерживает квалификаторы `assignee:LOGIN`, `review-requested:LOGIN` и `mentions:LOGIN`; каждый запрос ограничен открытыми записями одного разрешённого репозитория. GitHub может включать запрос ревью команды пользователя в результаты `review-requested`. [Справка по квалификаторам поиска](https://docs.github.com/en/search-github/searching-on-github/searching-issues-and-pull-requests)
- `githubHttp.ts` запрашивает только `GET https://api.github.com/search/issues` по REST API версии `2026-03-10` и ограничивает ответы до 2 МиБ. URL перенаправлений, ссылки пагинации и URL из ответа не используются для сетевых запросов. Обязательные поля ответа проверяются по типу и диапазону, ссылка должна соответствовать ожидаемому репозиторию, типу и номеру записи.
- `runner.ts` передаёт проверенные черновики в репозиторий Hub от имени источника `connector:github`. Для `externalId` используется числовой `id` записи в GitHub Search. Ключ идемпотентности вычисляется как SHA-256 от строки внешнего идентификатора. SQLite фиксирует создание, изменение для sync и аудит атомарно с ключом. Повторный импорт и переименование источника не заменяют существующую карточку. Ограниченный кэш недавно обработанных идентификаторов сокращает число обращений к таблице ключей. Если импорт прерван после части локальных записей, следующий цикл дозапишет остальные без дубликатов.

## Конфигурация и права

Публичная конфигурация содержит GitHub-логин, от одного до трёх явно указанных репозиториев в формате `owner/repository` и необязательную пару `boardId` и `columnId`. GitHub Search поддерживает fine-grained personal access tokens без дополнительных разрешений на сам endpoint. Для приватных источников токену всё равно нужен доступ к выбранным репозиториям согласно ограничениям GitHub и организации. Значение токена Hub получает из `DASHFLOW_HUB_GITHUB_TOKEN`. Токен отсутствует в JSON Schema, локальных карточках и состоянии опроса, не передаётся расширению и не выводится в URL или сообщениях об ошибках. [GitHub REST API Search](https://docs.github.com/en/rest/search/search#search-issues-and-pull-requests)

Поддерживаются личные упоминания, видимые в индексе Search. Результаты зависят от свежести индекса и доступа токена. Лента Inbox GitHub, прочитанность, история событий и упоминания команды `team_mention` недоступны через этот контракт. Endpoint `GET /notifications` поддерживает classic PAT со scope `notifications` или `repo` и не поддерживает fine-grained PAT. Коннектор не вызывает этот endpoint и не запрашивает расширенные права. [GitHub REST API Notifications](https://docs.github.com/en/rest/activity/notifications#list-notifications-for-the-authenticated-user)

Hub сохраняет заголовок и каноническую веб-ссылку. Описания, комментарии, авторы и участники не копируются. Заголовок приходит от внешней стороны и остаётся недоверенным содержимым при показе и передаче агентам.

## Расписание и отказоустойчивость

Опрос по умолчанию запускается раз в 5 минут. Допустимый интервал от 1 минуты до 24 часов. На запрос отведено 8 секунд, на цикл — 3 минуты. Сетевой сбой и ответ 408 или 5xx допускают один повтор через 250 мс. При 429 и распознанном ограничении 403 следующий опрос откладывается с учётом `Retry-After` и `X-RateLimit-Reset`; при неизвестном сроке применяется пауза не менее минуты. Статус и срок паузы восстанавливаются из файла, назначенного в конфигурации Hub. [Рекомендации GitHub по лимитам REST API](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api#handle-rate-limit-errors-appropriately)

Цикл выполняет по пять поисков на репозиторий, до двух страниц по 50 записей на поиск. Выбираются наиболее недавно обновлённые записи. Если GitHub сообщает о неполных результатах или размер найденных данных превышает лимит, доступные карточки импортируются со статусом цикла `INCOMPLETE`. Это периодический срез текущего состояния, поэтому событие, исчезнувшее из поиска между опросами, может быть пропущено.

`state.ts` сохраняет время попытки и успеха, состояние, безопасный код последней ошибки и срок паузы. Запись использует соседний временный файл с правами 0600 на POSIX и атомарную замену. Каталог должен принадлежать владельцу экземпляра Hub. На один файл состояния рассчитан один процесс Hub; файл содержит эксплуатационные метаданные, а дедупликация остаётся в SQLite. Остановка завершает таймер, отменяет запросы и дожидается текущего опроса. Удаление или отключение конфигурации останавливает импорт, уже сохранённые карточки остаются в Hub. Схема SQLite не меняется.

Проверки `hub/test/connectorsGitHub.test.ts` используют синтетические ответы и временную SQLite. Фактический доступ токена к репозиторию и задержка индекса GitHub зависят от аккаунта и настроек организации.
