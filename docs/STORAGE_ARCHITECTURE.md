# Архитектура хранилища и миграций (Storage & Migrations Architecture)

## 1. Введение и назначение

Модуль `@/core/storage` отвечает за надёжное сохранение настроек, макетов сетки дашборда и пользовательских данных как в среде расширения Chrome (`chrome.storage.local`), так и в стандартном веб-окружении (`localStorage`, `IndexedDB`).

---

## 2. Структура модуля

```
src/core/storage/
├── keys.ts                # STORAGE_KEYS (реестр констант ключей и резервных копий)
├── errors.ts              # Типизированные ошибки (StorageQuotaExceededError, StorageError)
├── StorageAdapter.ts      # Универсальный адаптер сохранения и чтения
├── dashboardMigrations.ts # Чистые функции миграции состояния v1 -> v2 и адаптивных раскладок
├── dashboardSpaces.ts     # Снимок v3, чтение прежних раскладок и экспорт пространств
└── index.ts               # Единый реэкспорт
```

---

> **Содержимое рабочего пространства** (задачи, заметки, ссылки, доски, с этапа 2 — Inbox, напоминания, дайджесты) переезжает в отдельную базу IndexedDB `dashflow_items` — см. [`ITEMS_ARCHITECTURE.md`](ITEMS_ARCHITECTURE.md) и ADR-017. `StorageAdapter` остаётся для настроек, темы, раскладки и служебных ключей.

## 3. Реестр ключей хранилища

Все ключи строго типизированы и определены в `STORAGE_KEYS`:
- `DASHBOARD`: `'dashflow_dashboard_store'` — основное состояние дашборда.
- `DASHBOARD_BACKUP_V1`: `'dashflow_backup_v1'` — резервная копия состояния v1 перед миграцией (Правило 51).
- `DASHBOARD_BACKUP_V2`: `'dashflow_backup_v2'` — полный снимок Zustand `{ state, version: 2 }` перед первым сохранением v3.
- `THEME`: `'dashflow_theme_store'` — настройки темы.
- `THEME_BACKUP_V1`: `'dashflow_theme_backup_v1'` — резервная копия темы v1.
- `APP_SETTINGS`: `'dashflow_app_settings'` — глобальные настройки приложения.
- `WALLPAPER_BLOB`: `'dashflow_wallpaper_blob'` — пользовательские обои (IndexedDB).
- `WEATHER_CACHE`: `'dashflow_weather_cache'` — кеш метеоданных (IndexedDB).
- `PLUGIN_DATA_PREFIX`: `'dashflow_plugin_'` — префикс изолированных данных сторонних плагинов.
- `WIDGET_DATA_KEYS`:
  - `NOTES`: `dashflow_notes_text_${instanceId}` (базовый: `dashflow_notes_text`)
  - `TODO`: `dashflow_todo_items_${instanceId}` (базовый: `dashflow_widget_todo_items`)
  - `QUICKLINKS`: `dashflow_quicklinks_list_${instanceId}` (базовый: `dashflow_quicklinks_list`)

---

## 4. Обработка квот и больших данных (Правило 25)

- Для небольших конфигурационных структур используется `StorageAdapter.get` / `StorageAdapter.set`.
- Для больших бинарных данных (обои, кеш) реализованы `setLarge` / `getLarge`, использующие `IndexedDB` (`idb`).
- При переполнении квоты распознаются коды ошибок браузера (код 22, 1014, имя `QuotaExceededError`) и выбрасывается `StorageQuotaExceededError`, предотвращая скрытое повреждение данных.

## 5. Миграции Dashboard Store

- Состояние v1 хранило плоский массив `widgets` с фиксированными координатами `x`, `y`, `w`, `h` для одной сетки 12 колонок.
- Состояние v2 разделяет `instances` (идентификаторы и настройки) и `layouts` (адаптивные раскладки для 5 брейкпоинтов: `xl`, `lg`, `md`, `sm`, `xs`).
- Функция `deriveResponsiveLayouts(baseLayout, baseCols)` автоматически рассчитывает плотную адаптивную сетку для мобильных и планшетных устройств, гарантируя отсутствие горизонтального скролла (Правила 8–10).

### 5.0. Содержимое виджетов (`userContent.ts`)

- Задачи, привычки, заметки и быстрые ссылки живут вне стора дашборда: в общем ключе (`TODO_ITEMS`, `HABIT_ITEMS`, `NOTES_CONTENT`, `QUICK_LINKS`) и в копии экземпляра `<ключ>_<instanceId>`.
- `collectUserContent(instanceIds)` собирает их для экспорта, `restoreUserContent(snapshot)` восстанавливает при импорте.
- Импорт пишет только эти ключи (`contentKindOf`, id экземпляра — `[A-Za-z0-9_-]{1,100}`) и только значения, прошедшие проверку формы и лимитов `USER_CONTENT_LIMITS`. Чужие ключи (права, плагины, дашборд) и невалидные значения отбрасываются целиком — файл не может перезаписать произвольные настройки.

### 5.1. Что сохраняет `useDashboardStore`

- Снимок v3 сохраняет `version`, `spaces`, `activeSpaceId` и общие поля `layoutMode`, `heroSettings`, `speedDialLinks`. В каждом пространстве есть `id`, `title`, необязательная `icon`, а также `baseColumns`, `gap`, `instances`, `layouts`. Пустой заголовок исходной сетки означает локализованное имя «Главная».
- Состояние UI (`activeModal`, `isEditMode`, `isCommandPaletteOpen`) живёт только в памяти: после перезагрузки вкладка открывается без модалок и вне режима правки.
- При переходе v2 → v3 старая сетка становится пространством `home` с прежними id экземпляров и раскладками всех пяти брейкпоинтов. Приложение ждёт завершения гидратации перед монтажом виджетов. Если резервная запись или перенос не удались, вкладка показывает ошибку и позволяет повторить загрузку.
- Сохранения v1 с `widgets` читаются через `migrateDashboardState`, затем оборачиваются в пространство. Экспорт 3.0 содержит список пространств и плоскую копию активной сетки для 3.8.
- Для отката с v3 к исходной сетке закрыть вкладки DashFlow, сохранить актуальный экспорт и восстановить значение `dashflow_backup_v2` в `dashflow_dashboard_store` перед запуском старой сборки. Такой откат восстанавливает раскладку на момент миграции. Актуальный экспорт нужен для сохранения более поздних изменений.

## 6. Изоляция данных мульти-инстансов виджетов (Multi-instance Isolation)

Экземпляры Todo, «Заметок» и «Быстрых ссылок» привязаны к доске или записи Item через свои настройки. Старые ключи служат источником миграции и входят в экспорт для совместимости. Привычки продолжают работать со своим прежним форматом. Подробности приведены в [архитектуре Item](ITEMS_ARCHITECTURE.md#53-виджеты-на-item-шаг-14).
