# Базовый профиль производительности расширения

Замеры выполнены 24 ноября 2026 года на готовой локальной сборке `.output/chrome-mv3`, без пересборки и внешней сети. Это воспроизводимая точка отсчёта для последующего сравнения; значения не являются пользовательским SLO и не управляют бюджетом сборки.

## Окружение

- Расширение: версия manifest `4.0.0`, артефакт изменён `2026-11-24T10:14:07Z`.
- Chromium `156.0.8078.4`, headed mode, Playwright channel `chromium`.
- Windows 11, build `10.0.26300`, Node.js `v22.22.0`.
- Intel Core i7-13700KF, 24 logical CPU; RAM 31.8 GiB.
- Viewport 1365×900, device scale factor 1, без CPU throttling.
- Браузерные профили создавались во временном каталоге отдельно для каждого сценария; Chromium работал offline, запросы HTTP(S) прерывались, фоновая сеть выключена.

## Методика и наблюдения

Холодная выборка использует новый временный профиль и первое открытие `newtab.html`; в кадре виден онбординг. Тёплая выборка сделана после закрытия онбординга и повторной загрузки стандартного пространства с пятью виджетами. Это пользовательские состояния с разным содержимым, поэтому их разница не изолирует только влияние дискового кеша браузера.

Для плотного сценария в новом временном профиле через UI добавлены 24 синтетических экземпляра Clock к пяти стандартным виджетам. Память измерялась через CDP `Runtime.getHeapUsage` после `HeapProfiler.collectGarbage`, DOM и listeners — через `Memory.getDOMCounters`. Три измерения выполнены после повторных загрузок одного синтетического профиля; heap использован оставался в диапазоне 7.4–7.5 MiB, а число DOM nodes и listeners совпадало между выборками.

«Первый видимый интерактивный control» — локальная метка времени от начала навигации до появления первого видимого активного `button`, `input`, `select`, `textarea` или ссылки внутри приложения. Это отдельное пользовательское измерение, оно **не называется Lighthouse TTI**. LCP собирался `PerformanceObserver` и фиксировался после появления первого control и короткого окна стабилизации.

Профиль можно повторить командой `node scripts/profile-extension.mjs`. Число пар cold/warm настраивается `--samples=5` (допустимо 3–10), число добавляемых тестовых виджетов — `--widgets=24` (20–100). Скрипт открывает окно Chromium, изменяет только собственные временные профили и удаляет их после измерения. Он не публикует артефакты, не меняет пользовательские профили и не проверяет порог производительности.

Значения зависят от версии Chromium, локальной нагрузки системы, файлового кеша ОС, размера viewport и кода собранного артефакта. При сравнении нужно сохранять эти условия и число выборок; перед следующим baseline проверить, что `.output/chrome-mv3` соответствует нужной версии приложения.
