# Telegram в локальном Hub

Hub создаёт заметки во «Входящих» из новых текстовых сообщений, полученных ботом в явно разрешённых чатах. Дополнительная настройка позволяет отправлять заголовок локальной карточки с наступившим `remindAt` в один из этих чатов.

## Компоненты и поток данных

- `telegram.ts` связывает Telegram со штатным опросом Hub. Перед запуском проверяет токен, список chat ID и назначение для напоминаний. Входящий текст сохраняется как заметка с источником Telegram. Правила чтения Hub применяются к ней как к другим локальным заметкам.
- `telegramHttp.ts` реализует только `getUpdates` и `sendMessage`. Запросы идут по TLS на фиксированный `api.telegram.org` с JSON в теле. API требует токен в пути. Hub запрещает перенаправления, ограничивает ответ до 512 КиБ, запрос до 20 секунд и проверяет обязательные поля ответа. Ошибки сведены к кодам без путей и текста ответов. [Формат запросов Telegram Bot API](https://core.telegram.org/bots/api#making-requests)
- `telegramState.ts` хранит offset, время последнего пакета, позицию сканирования напоминаний и журнал доставки в отдельной SQLite по пути `${statePath}.sqlite`. Файл создаётся с правами 0600 на POSIX в каталоге владельца Hub. Состояние опроса и последняя ошибка сохраняются штатным runner в JSON `statePath`.
- `telegramReminders.ts` обходит карточки ограниченными страницами. Позиция обхода сохраняется между циклами, чтобы проверять старые карточки. Непрерывное изменение коллекции может увеличить задержку.

## Настройка и изоляция

Hub получает токен из `DASHFLOW_HUB_TELEGRAM_TOKEN`. Настройки содержат до 100 точных числовых chat ID, представленных десятичными строками, включая отрицательные ID групп. Необязательный `reminderChatId` должен совпадать с одной записью списка. Имена пользователей, wildcard и перенос назначения по предложению Telegram исключены. Любой участник разрешённой группы, чьи сообщения доступны боту, может создать заметку.

Hub запрашивает обновления `message`. Другие типы обновлений, чаты вне списка, сообщения без текста и вложения пропускаются. Текст воспринимается как недоверенные данные без интерпретации команд или разметки. Идентификаторы участников, метаданные групп и вложения не сохраняются. Если текст содержит точное значение токена этого бота, Hub заменяет его перед записью или отправкой.

Бот должен использоваться одним экземпляром опроса. Telegram исключает одновременный `getUpdates` и активный webhook. Коннектор не меняет настройки webhook и группы. Telegram хранит ожидающие обновления до 24 часов. Доступ к сообщениям групп зависит от privacy mode и прав бота. [Получение обновлений](https://core.telegram.org/bots/api#getting-updates), [Telegram Bots FAQ](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get)

## Подтверждение входящих сообщений

Цикл запрашивает до 25 обновлений с long polling до 10 секунд. После записи всех подходящих заметок Hub сохраняет offset, превышающий наибольший полученный `update_id`, включая пропущенные обновления. Следующий вызов подтверждает их на стороне Telegram. Сбой между сохранением заметки и offset вызовет повтор, который погасит существующий ключ идемпотентности SQLite, вычисленный из ID бота, чата и сообщения. Ротация токена того же бота сохраняет идентичность импорта. [Семантика offset](https://core.telegram.org/bots/api#getupdates)

Telegram может назначить новый случайный `update_id` после недели без обновлений. После шести дней без нового пакета Hub начинает опрос с нулевого offset. Сетевой сбой обрабатывается очередным плановым опросом с сохранённой позицией. Интервал по умолчанию — одна минута. Полный пакет отмечается как `INCOMPLETE`, чтобы было видно, что возможен остаток очереди. [Тип Update](https://core.telegram.org/bots/api#update)

## Напоминания

При включённой отправке Hub проверяет карточки с `remindAt` от текущего момента до 24 часов назад и пропускает завершённые, архивные и удалённые. За цикл отправляется до одного заголовка в настроенный чат. Hub отправляет заголовок обычным текстом и выключает предпросмотр ссылок. В разрешённой группе его смогут прочитать участники группы. [Вызов sendMessage](https://core.telegram.org/bots/api#sendmessage)

До отправки Hub фиксирует попытку в SQLite с уникальным ключом из ID бота, карточки и времени `remindAt`. Изменение времени создаёт новое напоминание. Telegram не предоставляет ключ идемпотентности для `sendMessage`, поэтому при внезапной остановке, таймауте или другом неопределённом сбое Hub сохраняет попытку и не посылает её снова. Это допускает потерю отдельного напоминания при сбое, но исключает повторную отправку из-за рестарта с сохранённым журналом. При подтверждённом ответе Telegram 429 Hub снимает отметку попытки и ждёт `retry_after` перед повтором. Журнал очищается через семь дней после даты напоминания. [ResponseParameters](https://core.telegram.org/bots/api#responseparameters)

## Эксплуатация и проверка

Отключение коннектора останавливает импорт и отправку. Локальные заметки сохраняются. Схема основной SQLite не меняется. Резервная копия состояния должна включать основную базу и SQLite коннектора. Восстановление устаревшей копии журнала может повторить ранее доставленное напоминание. Синтетические тесты используют подмену `fetch` и временную SQLite. Подключение реального бота и доставку в реальные чаты они не проверяют.
