# Резервное копирование и восстановление DashFlow

**Обновлено:** 2026-10-30. Документ описывает только то, что реально существует. Прежняя версия
описывала скрипты и дашборды, которых в проекте нет.

## 1. Что и где хранится

| Данные | Где | Кто отвечает за копию |
|---|---|---|
| Раскладка, тема, настройки, задачи, привычки, заметки, ссылки | Браузер пользователя: `chrome.storage.local` / IndexedDB `dashflow_db` (`StorageAdapter`) | Пользователь (экспорт в файл) |
| Исходный код, документация, история | GitHub `denis-ershov/dashflow` и локальный клон | Разработчик |
| Пакеты релизов (`.zip`) | GitHub Releases (workflow `release.yml` по тегу `v*`), магазины | Разработчик |

Облачной синхронизации и серверов нет: если пользователь удалит расширение без экспорта, данные
восстановить нельзя. Это сказано в политике конфиденциальности.

## 2. Пользовательские данные: экспорт и импорт

Настройки → «Данные» → «Скачать JSON-конфигурацию» / «Импорт».

**Формат экспорта** (`ImportExportModal`, версия файла `2.2`):
```json
{
  "version": "2.2",
  "exportedAt": "2026-10-29T12:34:56.789Z",
  "theme": { "activePresetId": "...", "wallpaperUrl": null, "scrim": 0.4, "customCss": "" },
  "dashboard": {
    "version": 2,
    "baseColumns": 12,
    "gap": 16,
    "layoutMode": "modular",
    "heroSettings": { ... },
    "speedDialLinks": [ ... ],
    "instances": [ { "instanceId": "clock-1", "widgetId": "clock", "settings": { ... } } ],
    "layouts": { "xl": [ ... ], "lg": [ ... ], "md": [ ... ], "sm": [ ... ], "xs": [ ... ] }
  },
  "settings": { "language": "ru" },
  "content": {
    "dashflow_widget_todo_items": [ { "id": "1", "text": "...", "completed": false, "priority": "medium" } ],
    "dashflow_widget_todo_items_todo-1": [ ... ],
    "dashflow_widget_habit_items": [ ... ],
    "dashflow_widget_notes_content_notes-1": "# ...",
    "dashflow_widget_quick_links": [ { "id": "l1", "title": "GitHub", "url": "https://github.com" } ]
  }
}
```
**Имя файла:** `dashflow-config-<timestamp>.json`

**Процесс экспорта:**
1. Пользователь нажимает «Скачать JSON Конфигурацию» в настройках
2. DashFlow берёт сохраняемую часть стора дашборда (`pickPersistedDashboard`), тему и язык
3. Сериализует в JSON и скачивает через `Blob` + `<a download>`

**Импорт:** принимает файлы `2.0`–`2.2` и старые файлы с плоским массивом `widgets` (через `migrateDashboardState`). Язык применяется, только если он поддерживается (`isSupportedLanguage`); тема проходит `migrateThemeState` и валидацию CSS.

**Содержимое виджетов** (с версии `2.2`): задачи, привычки, заметки и быстрые ссылки — общие ключи и копии каждого экземпляра `<ключ>_<instanceId>` (`collectUserContent`). При импорте `restoreUserContent` пишет только эти ключи и только значения, прошедшие проверку формы и лимитов (до 1000 элементов, 2000 символов на поле, 100 000 на заметку, ссылки только http/https); остальное отбрасывается. Файлы без поля `content` содержимое не трогают.

**Не входят:** установленные плагины и их данные (восстановление из файла обошло бы окно согласия на права), журнал сбоев, кэш погоды, флаги функций.

**Важно:**
- ✅ Экспорт не содержит секретов или токенов (их нет)
- ✅ Можно безопасно хранить в Dropbox/Google Drive
- ⚠️ Файл содержит личные данные (заметки, задачи) — не публиковать.

## 3. Код и релизы

- Основная копия — GitHub. Локальный клон — вторая копия; при потере аккаунта код восстанавливается из клона в новый репозиторий.
- Каждый тег `v*` публикует zip-пакеты Chrome и Firefox в GitHub Releases — это архив всех выпущенных версий для отката (см. `ROLLBACK_STRATEGY.md`).
- Архив исходников для AMO: `npm run zip:firefox` → `.output/dashflow-<version>-sources.zip`.

## 4. Проверка восстановления

Перед каждым релизом с изменениями формата данных:
1. Экспортировать данные из текущей версии.
2. Установить новую сборку в чистый профиль, импортировать файл.
3. Убедиться, что раскладка, задачи, заметки и ссылки на месте.

Автоматически это покрывают `tests/unit/core/userContent.test.ts` (экспорт → импорт содержимого) и
`tests/unit/core/dashboardMigrations.test.ts` (миграции старых форматов).

## 5. RTO / RPO

- **Пользователь:** RPO — момент последнего экспорта; RTO — минуты (импорт файла).
- **Код:** RPO — последний push; RTO — минуты (клон из GitHub).
