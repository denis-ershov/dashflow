# MCP и управление агентами DashFlow

## Точка подключения

Hub подключает клиентов через `dashflow-hub mcp` по stdio и через `POST /mcp` по Streamable HTTP. Оба транспорта используют существующие токены Hub. Stdio получает токен через переменную окружения `DASHFLOW_HUB_TOKEN` и оставляет stdout протоколу. HTTP принимает Bearer и проверяет Host и Origin. По умолчанию разрешены локальные адреса, а удалённый Hub обслуживается через HTTPS и настроенный `mcpAllowedHosts`.

`hub/src/mcp/server.ts` регистрирует 11 инструментов и три ресурса. Метаданные доступны на русском и английском. `workspace.ts` проверяет области токена, использует тот же SQLite-репозиторий, что и REST, и ограничивает объём выдачи. Тексты рабочего пространства считаются данными. Они возвращаются в структурированном результате с пометкой о недоверенном содержимом. Окружение агента решает, когда нужны подтверждения владельца.

HTTP не создаёт серверных MCP-сессий. Записи MCP на HTTP делят лимит запросов с REST. Stdio ограничивает объём входного сообщения и частоту записей в рамках процесса. Отозванный токен перестаёт работать в активном MCP-клиенте при следующем вызове.

## Назначение задачи

Палитра создаёт задачу со статусом `todo`. Из карточки Kanban можно поручить существующую задачу. Расширение сохраняет `assignee: "agent:<id>"` через командную шину и синхронизирует запись с Hub. Допустимый получатель имеет действующий токен агента и области чтения и записи Items.

Агент получает свои задачи через `list_items({assignee: "me"})`. Для чужой назначенной записи агент может обновить статус задачи и поле `agentComment`. Идентификатор владельца и исходное описание сохраняются. Отдельная область `items:manage` позволяет управлять чужими записями в рамках выданных прав.

## Управление доступом и откат

Список агентов, отзыв и откат доступны через настройки подключённого расширения. Устройство запрашивает метаданные, включая области, последнюю активность и число созданных записей. Секреты в эти ответы не входят. Входящие фильтруются по источнику, а в карточке Kanban показывается отметка агента и его комментарий.

SQLite v2 добавляет в журнал автора и снимок до записи. Предварительный просмотр показывает количество операций в периоде и сколько можно отменить. Hub сверяет подпись предпросмотра и то, что итоговый набор операций остался прежним. Поздние правки других участников сохраняются. За один запрос рассматривается до 100 операций. При откате новых записей используется мягкое удаление, а результат публикуется в журнале синхронизации. Записи журнала до миграции SQLite v2 остаются доступными для синхронизации.

Для возврата на Hub 0.1 используйте резервную копию SQLite v1 и прежний пакет. Перед откатом экспортируйте актуальные браузерные данные. Инструменты проверены через MCP SDK с настоящим Fastify на loopback и CLI-процессом на синтетической SQLite. Примеры настройки внешних клиентов хранятся в [каталоге агентов](agents/).
