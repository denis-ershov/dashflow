# Регламент отката релизов и аварийного восстановления (Rollback Strategy)

**Дата создания:** 30 сентября 2026  
**Версия:** 1.0.0  
**Статус:** Production Ready

---

## 1. Обзор архитектуры распространения и ограничения

Расширение DashFlow распространяется через официальные каталоги:
- **Chrome Web Store (CWS)**
- **Firefox Add-ons (AMO)**

### Ключевые ограничения магазинов расширений:
1. **Отсутствие мгновенного отката на стороне магазина:** Ни Chrome Web Store, ни Mozilla AMO не поддерживают мгновенный откат ("Rollback to vX.X.X") нажатием одной кнопки.
2. **Время модерации:** Любая новая версия (включая hotfix) проходит автоматическую проверку и ручную модерацию (от 15 минут в Firefox до 24–48 часов в Chrome).
3. **Постепенное автообновление:** Браузеры пользователей обновляют расширения в фоновом режиме (обычно раз в 4–6 часов).

## 2. Уровни критичности инцидентов (Severity Levels)

| Уровень | Описание | Примеры | Действие |
|---|---|---|---|
| **SEV-1 (Critical)** | Полный крах вкладки New Tab (белый экран, циклический reload, порча данных) | Ошибка в `RootErrorBoundary`, поломка схемы `StorageAdapter` | Экстренный Hotfix + аварийный сброс |
| **SEV-2 (Major)** | Падение ключевого виджета или утечка памяти | Зависание `weatherService`, сбой `ClockWidget` | Отключение через Feature Flag / Патч |
| **SEV-3 (Minor)** | Визуальные дефекты, ошибки локализации | Неправильный отступ, опечатка в i18n | Плановый релиз следующей версии |

## 3. Регламент экстренного отката (Rollback Runbook)

### Сценарий 1: Аварийный откат версии (Hotfix Release)

Если в опубликованной версии `vX.Y.Z` обнаружен критический SEV-1 дефект:

1. **Определение стабильной версии:**
   Найти последний стабильный Git-тег (например, `v3.7.1`).

2. **Создание хотфикс-ветки:**
   ```bash
   git checkout -b hotfix/rollback-to-v3.7.1
   ```

3. **Бамп патч-версии:**
   Магазины расширений требуют **строго возрастающий номер версии** (`vX.Y.Z+1`).
   В `package.json` установить новую версию (например, `3.7.3`).

4. **Формирование билда:**
   ```bash
   npm ci
   npm run compile
   npm run lint
   npm test
   npm run build:all
   npm run zip:all
   ```

5. **Публикация Hotfix в каталоги:**
   - Chrome Web Store Developer Dashboard → Package → Upload new package (`dashflow-3.7.3-chrome.zip`).
   - Отметить признак: *"This submission fixes a critical bug affecting user experience"*.
   - Загрузить в Mozilla AMO (`dashflow-3.7.3-firefox.zip` и `sources.zip`).

## 4. Восстановление данных пользователя (Storage Recovery)

### Автоматический резервный снапшот:
При каждой миграции структуры данных модуль `StorageAdapter` автоматически сохраняет снапшот предыдущего состояния:
- `STORAGE_KEYS.DASHBOARD_BACKUP_V1`
- `STORAGE_KEYS.THEME_BACKUP_V1`

### Процедура самовосстановления:
Если `RootErrorBoundary` перехватывает фатальный сбой рендеринга страницы, пользователю предоставляются безопасные действия в один клик:
1. **«Обновить страницу»** (`window.location.reload()`) — устранение временных сетевых коллизий.
2. **«Сбросить расположение виджетов»** — восстанавливает дефолтную сетку, сохраняя пользовательские заметки, задачи и темы в безопасности.

## 5. Аварийное отключение сбойных компонентов (Circuit Breaker & Feature Flags)

Если внешний сервис (Open-Meteo, Unsplash, Geocoding) перестает отвечать:
- Автомат `CircuitBreaker` переходит в состояние `OPEN`.
- Запросы блокируются локально, предотвращая спам сети и зависание браузера.
- Виджет мгновенно переходит в режим отображения кэша (`isOffline: true`).

Если сбой вызван экспериментальной функцией:
- Пользователь может выключить флаг в меню **«Настройки» → «Диагностика и система» → «Флаги функциональности»**.
