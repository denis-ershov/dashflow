# Цели качества (SLO) DashFlow

**Обновлено:** 2026-10-30. DashFlow — личный инструмент, который публикуется в магазинах, без
серверов и телеметрии. Поэтому цели ограничены тем, что реально измеряется: CI, локальная
диагностика и сигналы магазинов. Прежняя версия описывала churn-метрики и дашборды, которых нет.

## Цели

| # | SLI (что измеряем) | SLO (цель) | Источник | Что делаем при нарушении |
|---|---|---|---|---|
| 1 | Новая вкладка показывает контент (LCP) | ≤ 1,2 с на тёплом старте | `WebVitalsMonitor`, вкладка «Диагностика» | Профилировать, вернуть в бюджет до следующего релиза |
| 2 | Зелёные запуски CI на `main` | 100% (красный `main` не живёт дольше дня) | GitHub Actions | Новые функции не вливаются, пока `main` красный |
| 3 | Покрытие тестами | Не ниже порогов в `vitest.config.ts` (сейчас 78/69/58/78) | `npm run test:coverage` | CI падает; добавить тесты, а не снижать порог |
| 4 | Уязвимости high/critical в рабочих зависимостях | 0 | `npm audit --omit=dev`, Dependabot | Исправить в течение 7 дней, critical — сразу |
| 5 | Потеря данных пользователя при обновлении | 0 случаев | Issues, отзывы, тесты миграций | SEV-1, сценарий A в `INCIDENT_RESPONSE.md` |
| 6 | Ответ на issue об ошибке | ≤ 48 часов | GitHub Issues | — |

## Бюджет ошибок

- Нарушение SLO 2, 4 или 5 останавливает работу над новыми функциями до исправления.
- SLO 1 проверяется перед каждым релизом; ухудшение больше чем на 20% — блокер релиза.
