# ADR-005: Трёхслойная архитектура токенов дизайн-системы

## Статус
Принято (Accepted)

## Контекст
Прямое использование случайных CSS-переменных и произвольных Tailwind utility-классов приводило к фрагментации интерфейса, наложению стилей, неконсистентным отступам и z-index коллизиям между виджетами и модальными окнами.

## Решение
Разделить систему токенов на три четко разграниченных слоя:
1. **Слой 1 — Структурные токены (`tokens.css`):**
   - Единая фиксированная шкала `z-index` (`--z-base` до `--z-toast`).
   - Шкала скруглений (`--radius-sm` ... `--radius-full`).
   - Тайминги анимаций $\le 250$ ms с кривой `--ease-expo` и отключением по `prefers-reduced-motion: reduce`.
   - Целочисленные отступы по фиксированной шкале.
2. **Слой 2 — Семантические токены темы (`--dashflow-*`):**
   - 24 ключевых цвета (`canvas`, `surface`, `fg`, `line`, `primary`, `secondary`, `accent`, `danger`, `warning`, `success`, `glassBg` и их состояния `hover`/`active`/`fg`).
   - Скаляры: радиусы и системные шрифты (без внешних запросов к Google Fonts).
3. **Слой 3 — Псевдонимы совместимости:**
   - Мост к легаси переменным (`--color-*`, `--glass-*`, `--shadow-*`) для предотвращения поломок существующего кода.
4. **Интеграция с Tailwind 4:**
   - Экспорт токенов в `@theme` и `@theme inline` для генерации утилит `bg-primary`, `text-fg`, `border-line`, `shadow-1` и т.д.
5. **Автоматический контроль (Guard):**
   - Набор тестов `scale.guard.test.ts` проверяет отсутствие неразрешенных цветов (`bg-red-500`, `text-white`), магических z-index (`z-50`) и половинных шагов отступов.

## Последствия
- Единый источник правды для всех компонентов интерфейса.
- Гарантированная консистентность визуального языка DashFlow.
- Отсутствие непредсказуемых наложений и всплытий окон.
