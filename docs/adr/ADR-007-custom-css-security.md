# ADR-007: Модель безопасности и валидация пользовательского CSS

## Статус
Принято (Accepted)

## Контекст
Возможность ввода произвольного пользовательского CSS в расширении браузера создает риски сетевых утечек приватности пользователя (IP-адрес, время открытия новой вкладки через фоновые сетевые запросы при `@import` или `url()`), а также потенциальных инъекций через устаревшие механизмы (`behavior:`, `-moz-binding:`).

## Решение
Реализовать строгую двухконтурную модель валидации пользовательского CSS в `src/core/theme/cssValidator.ts`:
1. **Лимит размера:** Общий объем пользовательского CSS не должен превышать 50 000 символов (`MAX_CSS_LENGTH`).
2. **Блокировка директивы `@import`:** Директива `@import` безусловно запрещена, так как она инициирует неконтролируемые внешние сетевые запросы браузера.
3. **Контроль схем в `url()` и `@font-face`:**
   - По умолчанию разрешены только безопасные локальные схемы: `data:` и `chrome-extension:`.
   - Внешние `https:` ресурсы запрещены по умолчанию и могут быть включены пользователем только через явный осознанный тумблер `allowExternalCss` с предупреждением в интерфейсе.
   - Схемы `http:`, `javascript:`, `file:` безусловно блокируются.
4. **Блокировка legacy-векторов:** Свойства `behavior` и `-moz-binding` запрещены.
5. **Очистка комментариев и строк:** Валидатор предварительно очищает блочные комментарии `/* ... */` и экранирует строки, предотвращая скрытие вредоносных директив внутри комментариев.
6. **Отказ целиком:** При обнаружении хотя бы одного нарушения CSS отклоняется целиком с возвратом понятного кода ошибки (`code: CssRejectionCode`) без частичного или искаженного применения.

## Последствия
- Полная защита от скрытых сетевых утечек и отслеживания действий пользователя третьими лицами.
- Сохранение гибкости кастомизации интерфейса для опытных пользователей.
