# ADR-018: Командная шина и отмена

**Дата:** 2026-10-30 · **Статус:** принято

## Проблема

Данные рабочего пространства будут менять интерфейс, импорт, агенты и коннекторы. Нужно: одна точка проверки входа, источник у каждого изменения, отмена ошибочных действий (удаление, перемещение, архив) и тот же набор операций для командной палитры, агентов (этап 4) и синхронизации (этап 3).

## Варианты

1. **Вызовы репозитория прямо из компонентов.** Просто, но проверка, источник и отмена размазываются по виджетам.
2. **Снимки состояния (undo = вернуть прошлый снимок).** Просто отменять, но снимок всей базы дорог, а откат снимка затирает чужие изменения (другая вкладка, агент).
3. **Команды с обратным действием.** Каждая команда: `validate` (вход `unknown`) → `execute` → `{ result, undo }`. Диспетчер ведёт историю.

## Решение

Вариант 3 (`src/core/commands/`):

- `createDispatcher({ context: { repository, source }, commands })`: `dispatch(type, payload, { coalesceKey, skipHistory })`, `undo()`, `canUndo()`, `peek()`, `subscribe()`.
- История — в памяти вкладки, последние 50 действий; операции (включая отмены) выполняются строго по очереди.
- **Отмена не затирает чужие правки:** перед откатом команда сверяет затронутые поля с тем, что она оставила; если запись изменили — `UndoConflictError`, пользователь видит «Не удалось отменить: запись уже изменена».
- **Склейка:** команды с одним `coalesceKey` в пределах 5 секунд — один шаг отмены (серия правок текста заметки); отменяется цепочкой от последней правки к первой.
- `commandBus` — шина интерфейса от имени `LOCAL_USER_SOURCE`; агенты и коннекторы получат свои диспетчеры со своим `source`.
- Интерфейс (`src/features/commands/undo.ts`): тост с кнопкой «Отменить» (`dispatchWithUndoToast`), `Ctrl+Z` / `Cmd+Z` вне полей ввода (`useUndoHotkey`).

## Последствия

- Плюсы: один реестр операций для UI, палитры, агентов и Hub; источник в журнале `changes`; безопасная отмена.
- Минусы: у каждой команды — своя логика отмены (покрыта тестами); история не переживает перезагрузку вкладки (журнал в хранилище остаётся для аудита).
- Изменение без фактических правок не создаёт версию и не попадает в историю.

## Не входит

Повтор (redo) — не нужен для сценариев этапов 1–2; добавляется вторым стеком без изменения контракта команд.
