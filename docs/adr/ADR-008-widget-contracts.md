# ADR-008: Строгие контракты виджетов, схема настроек и Code-Splitting

## Статус
Принято

## Контекст
В версии DashFlow v1 интерфейс `WidgetDefinition` содержал множественные типы `any`, прямой импорт компонентов виджетов без динамической загрузки (что раздувало начальный бандл `newtab`), а также не имел декларативной схемы настроек с автоматической валидацией.

## Решение
1. Ввести обобщенный манифест `WidgetDefinition<S = Record<string, unknown>>` со строгой типизацией схемы настроек `WidgetSettingFieldSchema<S>[]`.
2. Заменить статическое свойство `component` на функцию динамической загрузки `load: () => Promise<{ default: ComponentType<WidgetProps<S>> }>`.
3. Создать декларативный генератор форм `WidgetSettingsForm` на базе дизайн-системы DashFlow.
4. Реализовать чистый валидатор `validateWidgetSettings` для защиты состояния от повреждения некорректными данными.
5. Реализовать fallback-манифест в `WidgetRegistry.getOrFallback` для изоляции сбоев.

## Последствия
- **Положительные:** Полная типобезопасность, уменьшение размера начального бандла за счет code splitting, надежная валидация настроек.
- **Ограничения:** Требуется асинхронный импорт компонентов виджетов через `React.lazy` / `load()`.
