# ADR-009: Стратегия хранения данных, обработка квот и миграция v1 -> v2

## Статус
Принято

## Контекст
В версии DashFlow v1 данные сохранялись без типизированного реестра ключей, не обрабатывались квоты браузера на переполнение `localStorage`, а состояние дашборда хранило виджеты в виде одной плоской раскладки без адаптивности для мобильных устройств.

## Решение
1. Ввести строгий реестр `STORAGE_KEYS` с резервными ключами `DASHBOARD_BACKUP_V1` и `THEME_BACKUP_V1` (Правило 51).
2. Реализовать `StorageAdapter` с поддержкой переключения `chrome.storage.local` $\leftrightarrow$ `localStorage` $\leftrightarrow$ `IndexedDB` (`setLarge`/`getLarge`).
3. Распознавать ошибки переполнения квот (`isQuotaError`) и выбрасывать типизированное исключение `StorageQuotaExceededError`.
4. Реализовать чистую миграцию состояния `migrateDashboardState` с разделением на `instances` и адаптивные раскладки `layouts` для 5 брейкпоинтов (`xl`, `lg`, `md`, `sm`, `xs`).

## Последствия
- **Положительные:** Надежное хранение, защита от потери данных, адаптивная раскладка на экранах от iPhone SE до 4K, возможность отката миграции.
- **Ограничения:** Большие объекты (обои, кеш) должны сохраняться через `setLarge`.
