# ADR-010: Движок интернационализации (i18n) на базе нативных Intl API

## Статус
Принято

## Контекст
В интерфейсе присутствовали разрозненные непереведенные строки, отсутствовала строгая типизация ключей локализации и гарантия полноты перевода между русским и английским языками.

## Решение
1. Разработать легковесный типизированный модуль `@/core/i18n` без тяжелых внешних библиотек (типа `react-i18next`).
2. Выводить тип `TranslationKey` автоматически из `typeof ru` через рекурсивный `NestedKeyOf`.
3. Реализовать плюрализацию через `Intl.PluralRules` и форматирование через `Intl.DateTimeFormat` / `Intl.NumberFormat`.
4. Реализовать fallback-защиту: при отсутствии перевода брать русский вариант, при полном отсутствии возвращать безопасную заглушку `—` (никогда не показывать пользователю сырые пути ключей).
5. Гарантировать 100% равенство ключей словарей тестом `tests/unit/core/i18n.test.ts`.

## Последствия
- **Положительные:** Минимальный размер бандла (0 дополнительных зависимостей), строгая защита от ошибок в ключах во время компиляции, соответствие WCAG и правилам локализации.
- **Ограничения:** Добавление новых переводов требует синхронного обновления `ru.ts` и `en.ts`.
