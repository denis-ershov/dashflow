# Политика безопасности DashFlow (SECURITY)

Безопасность пользователей, изоляция конфиденциальных данных и строгое следование стандартам **Chrome Manifest V3** являются фундаментальными приоритетами проекта **DashFlow**.

---

## 🛡️ Поддерживаемые версии

Обновления безопасности и патчи уязвимостей выпускаются только для актуальной мажорной версии:

| Версия | Поддержка безопасности |
| :--- | :--- |
| **2.0.x** | ✅ Активно поддерживается |
| < 2.0.0 | ❌ Не поддерживается |

---

## 🔒 Модель безопасности DashFlow

### 1. Соответствие политике Chrome Manifest V3
- Полный отказ от выполнения удалённого кода (`remotely hosted code`), динамических выражений `eval()`, `new Function()` и внедрения внешних тегов `<script>`.
- Использование декларативных JSON-плагинов с жесткой валидацией схемы.

### 2. Изоляция песочницы iframe (Sandboxing)
- Все пользовательские плагины и виджеты, требующие отображения внешнего контента, изолируются в `iframe` со строгой директивой:
  ```html
  <iframe sandbox="allow-scripts" srcdoc="..." />
  ```
- ⚠️ **Комбинация `allow-scripts` + `allow-same-origin` строго запрещена!** Изолированный фрейм получает `origin: null` и не имеет доступа к API расширения `chrome.*`, `localStorage` или cookie родительского окна.

### 3. Защита RPC-моста (SandboxBridge)
- Обмен сообщениями между родительским приложением и песочницей через `window.postMessage` проверяется строго по источнику `event.source === iframe.contentWindow`.
- Доступ к хранилищу изолирован префиксом `dashflow_plugin_<pluginId>_<key>`.

### 4. Валидация Custom CSS
- Пользовательский CSS перед инъекцией в DOM проходит проверку через `validateCustomCss`:
  - Запрещены директивы `@import`.
  - Запрещены внешние `url()` со схемами `http:`, `https:`, `//` для предотвращения сетевой утечки данных и времени открытия вкладки.
  - Запрещены схемы `javascript:` и браузерные привязки (`-moz-binding`, `behavior`).

### 5. Менеджер чувствительных разрешений (Permissions Consent Flow)
- Запрос чувствительных прав Chrome (`network`, `bookmarks`, `geolocation`) требует отображения интерактивного модального окна `PermissionConsentModal` и явного согласия пользователя перед активацией.
- Разрешения могут быть отозваны пользователем в любой момент через настройки.

## 🚨 Как сообщить об уязвимости

Если вы обнаружили потенциальную уязвимость безопасности в проекте DashFlow, пожалуйста, **НЕ создавайте публичный Issue на GitHub**.

Вместо этого отправьте отчёт с описанием проблемы:
1. Опишите тип уязвимости и потенциальные последствия.
2. Предоставьте воспроизводимый сценарий (Proof of Concept).
3. Приложите скриншоты или логи, если применимо.

Мы обязуемся:
- Подтвердить получение отчёта в течение 48 часов.
- Провести аудит и предоставить предварительную оценку уязвимости.
- Выпустить исправление и уведомить вас до публичного раскрытия информации.

Спасибо за помощь в обеспечении безопасности пользователей DashFlow!
